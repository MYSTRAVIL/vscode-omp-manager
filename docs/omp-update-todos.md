## v18.4.3 -> v18.8.0 (checked 2026-10-07)
- [x] **Breaking** [v18.4.9, v18.5.0] A live session can now leave its file without any session event. When another omp process owns the file (`open-elsewhere`, including a resume through a symlink or hard link) or keeps rewriting it (`replaced`/`contested`), `SessionManager` continues in a sibling `<timestamp>_<newId>.jsonl` with a new session id and `parentSession` set to the old id, and announces it only through `sessionManager.onPersistenceNotice({ reason, from, to })`. The move happens on a write, and messages are written on `message_end`, after `agent_start`. The hook reads the path only when an event fires, so the terminal record can keep the old file until `agent_end`. Until then the sidebar maps the terminal to the old file, reopening that file launches another contested `--resume`, and a window closed mid-turn restores the old file. Evidence: `hook/vscode-session-restore.ts:50` `const sessionFile = sm.getSessionFile();` and `src/tracker.ts:211` `if (opts.sessionFile) args.push("--resume", opts.sessionFile);`. Action: in `session_start`, subscribe through the runtime `ctx.sessionManager.onPersistenceNotice` (duck-typed like `getSessionFile`; it replays earlier notices and is missing from the `ReadonlySessionManager` type), re-report when it fires, and sync the llm-dotfiles copy.
